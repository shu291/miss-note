# ミスノート

### → **https://shu291.github.io/miss-note/**

間違えた問題を撮るだけ。**復習日が自動で決まって、今日やるぶんだけ出てくる**間違いノート。

間違いノートは効果が高いのに「作るのが面倒」「作って満足して見返さない」で終わりがち。
このアプリはその2つだけを自動化しています。

- 登録は **写真1枚 ＋ タップ2回**（教科・原因）で終わり
- 使っている**参考書を登録しておくと、ホームのボタン1つで撮影に直行**（教科も自動で入る）
- 撮影は **完全無音**。授業中や図書館でも、聴いている音楽を止めずに撮れる
- 復習日は自動：**1日後 → 3日後 → 7日後 → 16日後 → 35日後 → 定着ずみ**
- 間違えたら2段階もどって、その日のうちにもう1回出る
- 「なぜ間違えたか」を集計して、自分のミスのクセを見せてくれる

## 使いかた

**https://shu291.github.io/miss-note/ を開くだけ。** インストールも登録も不要です。

初回だけ「ホーム画面に追加」をしておくと、
アプリのように開けて、オフラインでも動き、iPhone でデータが消えなくなります。

- **Android / PC の Chrome** … 画面に出る「ホーム画面に追加」ボタンを押す
- **iPhone** … Safari で開き、共有ボタン（□に↑）→「ホーム画面に追加」

> 開発中に手元で試すときは、`file://` だと写真の保存やオフライン機能が制限されるので、
> 簡易サーバー経由で開いてください。
>
> ```sh
> cd miss-note
> python3 -m http.server 8137
> # → http://127.0.0.1:8137/ を開く
> ```

## 更新のしかた

`index.html` を編集して push すると、1〜2分で公開ページに反映されます。

```sh
git add -A && git commit -m "変更内容" && git push
```

## 画面

アプリを開くと**「追加」から始まります**。授業中に「間違えた！」と思った瞬間、
開いてすぐ撮れるようにするためです。今日ぶんの復習が残っているときは、
下の「復習」タブに赤い数字が出ます。

| タブ | できること |
|---|---|
| 復習 | 今日ぶんの出題。答えを見て「できた／またミスした」を押すだけ。上に参考書のショートカット |
| 追加 | 写真（問題・解答）＋参考書＋ページ番号＋教科＋原因＋メモを登録。撮影は**無音カメラのみ**。**ページ全体から複数問まとめて**も登録できる |
| 一覧 | ためたミスをサムネイルで一覧・絞り込み（状態／教科／参考書）。参考書を選ぶと**その本のノート**になる。個別に「今すぐ復習」「やり直す」「削除」。**いま見えているぶんを印刷**できる |
| 分析 | 原因別・教科別・参考書別の内訳、**続けた記録（連続日数とカレンダー）**、2週間の登録数、しつこく間違えている問題。**参考書1冊だけに絞って見られる** |

## 仕組み

### 参考書とショートカット
⚙設定 →「参考書」で、使っている問題集（「青チャート数学ⅠA」など）を登録します。
教科をひもづけておくと、その参考書で登録したミスに教科が自動で入ります。

登録すると、**復習タブの上にワンタップのボタン**が並びます。
押すとその場で写真の選択が開き、参考書・教科が入った状態で撮影 → 原因をタップ → 登録。
登録後も追加画面に留まるので、**同じ本から続けてどんどん入れられます**（ボタンの数字はその本のミスの数）。

参考書は**教科ごとにまとまって**並びます（ショートカット・追加画面のチップ・設定・一覧の絞り込み、すべて）。

- 参考書の名前を変えると、登録ずみのミスの表示も一緒に変わります
- 参考書を削除してもミスは消えません。「どの本の問題だったか」はミス側にも残ります
- 参考書を選ばずに登録することもできます（そのときの動きは今までどおり）

### ページ・問題番号
参考書を選ぶと、**ページ**と**問題番号**の欄が出ます。欄をタップすると**アプリの中の10キー**が下に開きます。

iPad の OS キーボードは `inputmode="numeric"` にしても10キーにならずフルキーボードの数字面が出るだけなので、
入力欄を `inputmode="none"`（OSキーボードを出さない）にして、自前のキーパッドを出しています。

- ページ入力中は「次へ」で問題番号へ、問題番号では「完了」で閉じる
- 番号のそとをタップ／画面を移る／登録し終える と自動で閉じる
- 物理キーボードからの入力もそのまま効く（数字以外は落とす）

同じ本の**前回の番号を覚えていて**、次に登録するときは候補がワンタップで入ります。

| 候補 | 中身 |
|---|---|
| `p.132 問6` | 同じページの次の問題 |
| `p.132` | 同じページ |
| `p.133` | 次のページ |

番号は空のままでも登録できます（ノートでは末尾に「番号なし」として並びます）。

### 参考書ごとの復習ノート
一覧タブで参考書を選ぶ（または設定の「ノート」ボタン、分析の参考書カードから）と、**その本だけのノート**になります。

- 見出しがその参考書の名前になり、ミスが**ページ順**に並ぶ
- ページ範囲・ぜんぶ／復習中／定着ずみ／今日ぶんの数がひと目でわかる
- **「この本を通して復習する」** でその本の復習中のミスをページ順に通しで解き直せる
  （前倒し復習と同じ扱いで、記録は残るが復習日は動かない）

### 教科と「なぜ間違えた？」
教科は理系受験に使うものだけ（数学・英語・物理・化学・生物・地学・情報・その他）。

「なぜ間違えた？」の項目は **⚙設定 →「なぜ間違えた？の項目」** から自分の言葉に変えられます。

- 追加・名前の変更・削除ができ、「最初の6個に戻す」でいつでも初期値に戻せる
- 名前を変えると、登録ずみのミスの原因も一緒に変わる
- 項目を削除しても、その原因で登録したミスは消えない（原因の表示も残る）
- 説明を書いておくと、分析の対策コメントにそのまま出る

### 分析を参考書ごとに見る
分析タブの上の絞り込みで、**参考書1冊だけの分析**に切り替えられます。
「この本ではどのミスが多いか」がそのまま見えます。

絞っているあいだは、意味のなくなる「教科ごと」「参考書ごと」のカードは隠れます。

### iPad
横幅700px以上では、**下のタブはそのまま**に、本文の幅・文字・ボタン・写真が大きくなります。
一覧は3列以上、設定などのシートは下からせり上がる代わりに中央のダイアログになります。

### 復習スケジュール
正解するたびに次の間隔へ進み、5段階すべて通ると「定着ずみ」になります。
間違えると **2段階もどって翌日** に再出題（さらに、その日のセッションの最後にもう1回だけ出ます）。

### 1日の上限
たまりすぎて心が折れないよう、1日に出す数に上限（初期値20問）があります。
あふれたぶんは自動で翌日に回ります。設定（⚙）から5〜60問で変更できます。

### 無音カメラ

写真スロット（または参考書ショートカット）を押すと、**そのまま無音カメラが開きます。**
撮り方を選ぶ画面はありません。写真の入り口はこれ1つだけです。

標準の `<input type="file" accept="image/*">` から撮ると iPad はシステムのカメラを開くので、
**シャッター音が鳴り、再生中の音楽や動画が止まります。** このカメラはそのどちらも起きません。

- 写真撮影APIを使わず、プレビュー映像の1コマを `<canvas>` に写して画像化 → シャッター音の経路を通らない
- `getUserMedia` を **`audio: false`**（マイクを一切要求しない）／プレビューは `muted` + `volume=0` + `playsinline` + `disableRemotePlayback`
  → **Safari では Apple Music や YouTube を流したまま撮れます**（iOS が音を止める条件に当てはまらない）

中身は独立した Web コンポーネント `silent-camera.js`（[shu291/silent-camera](https://github.com/shu291/silent-camera)）で、
`<silent-camera no-gallery>` を置いて `capture` イベントを受けるだけ。撮ったあとは切り抜き画面に進みます。

カメラの権限が拒否されているなど、**どうしても起動できなかったときだけ**
「カメラが使えないので写真から選ぶ」ボタンが出ます（通常は表示されません）。

#### 音の使い方を宣言する（Audio Session API）

iOS は「そのページが音をどう使うか」で端末の音の設定を切り替えます。
何も宣言しないと自動判定になり、カメラを起こしたときに
**録音向け（play-and-record）や再生向け（playback）**に切り替わることがあります。
どちらも「他の音を止める」設定なので、聴いている音楽が止まります。

そこで `silent-camera` は、**カメラを使っているあいだだけ**
`navigator.audioSession.type = "ambient"`（＝他の音と混ざってよい）を宣言します。
WebKit の中では、この指定（`categoryOverride`）が自動判定より**優先**されます。

```
// MediaSessionManagerCocoa.mm ／ updateSessionState()
else if (captureCount || …)      category = PlayAndRecord;   // ← ここに落ちると音楽が止まる
…
if (sharedSession->categoryOverride() != None)
    category = sharedSession->categoryOverride();            // ← ページの指定が勝つ
```

- 宣言は **カメラを起こす前**に行う（起こしたあとでは、切り替わった設定を追いかけることになる）
- `stop()` で**元の種類に戻す**（組み込み先のページの音を邪魔しないため）
- 対応していないブラウザでは何も起きない（害もない）
- **保険**：ambient を宣言した状態でカメラが起動できなかったら、
  宣言を取り下げて一度だけやり直す。写らないより音楽が止まるほうがまだましなので
- カメラ画面の案内に、**宣言できたかどうかと端末の状態**を出している
  （直らないときはその中身がそのまま手がかりになる）

#### カメラを持ちつづけない（音楽を止めないための鉄則）

**撮り終わったらカメラを手放す。** これを破ると、再生中の音楽が止まったままになります。

一度 v10 で「許可を聞かれる回数を減らす」ために撮影後もカメラを 100秒 持ちつづける
作りにしたところ、**音楽が止まったまま戻らなくなりました**（v12 で既定を元に戻し済み）。
カメラを握っているあいだはブラウザが端末の音の権利も握るためで、
手放した瞬間に Apple Music などは再生を再開します。

`stop()` では**トラックを止めるだけでなく `video.srcObject` も外す**こと。
差したままだとブラウザが「まだ再生中」とみなし、音の権利を返さないことがあります。

| | 中身 |
|---|---|
| ⚙設定「カメラの持ちかた」 | **すぐ手放す**（既定）＝撮った瞬間に `stop()`／**持っておく**＝`KEEP_WARM_MS`（100秒）持ちつづける。**音楽を聴くなら既定のまま** |
| 裏に回ったら必ず手放す | `visibilitychange` で `camRelease()`。さらに `handleVisibility()` は**画面に出ていない（`offsetParent === null`）なら復帰しない** — 隠れたまま起き上がって音楽を二度止めないため |

#### 「許可を毎回聞かれる」について

iOS はブラウザに出したカメラの許可を**アプリを閉じると忘れます**。アプリ側からは覚えさせられません。

- **Safari** … 「ぁあ」→ Webサイトの設定 → カメラ →「許可」で**覚えてくれる**
- **Chrome / Edge（iPad）** … 中身が WebKit なので残せない。Safari に移すのが確実
- カメラ画面の「許可を毎回聞かれる・音楽が止まるときは」で、`camEnv()` によりブラウザ別の手順を表示

Safari に移す場合、**記録はブラウザごとに別**なので、
移る前に ⚙設定 →「書き出す」でバックアップを取り、Safari 側で読みこむこと。

#### 版の確認

⚙設定のいちばん下に版（`APP_VER`）を出しています。`sw.js` の `CACHE` と必ずそろえること。
「直したはずなのに直っていない」が古いキャッシュのせいかどうかを、これで切り分けます。

### ページから複数問をまとめて登録

追加タブの **「📄 ページ全体を撮って、まとめて登録」** で、
1ページを1回撮って問題ごとに切り分け、まとめて登録できます。

切り分けは2段構えです。

| | やりかた | 速さ | 使えるところ |
|---|---|---|---|
| **自動**（既定） | 写真の「行ごとの黒さ」を数え、**行間より明らかに広いすき間**を問題の切れ目とみなす | 一瞬 | 追加の部品なし・オフラインでも動く |
| **🔎 番号を読み取る** | 問題番号（`1.` `(2)` など）を**文字として読み取り**、その位置で区切って番号も入れる | 15秒ほど | ネットが必要 |

線はあとから直せます。**写真をタップで線を足す／線をタップで消す。**
サムネイルをタップすると、そのかたまりを「とばす」に切り替えられます
（章のタイトルなど、問題でないものを外すため）。

OCR は `tesseract.js` を **押したときだけ CDN から取りに行きます**。
アプリ本体（130KB）は重くなりません。また `cacheMethod: "none"` にしてあるので、
読み取り部品が**アプリの保存領域（IndexedDB）を1バイトも使いません**
＝「あと何問入るか」の数字が狂いません。

読ませるのは**ページの左はしの帯だけ**です。問題番号はそこにしか無く、
日本語は `eng` では読めないので、全面を読ませても遅くなるだけだからです。
実測で **67秒 → 15秒**（1500×2000 のページ → 201×2000 の帯）。

#### 容量

切り分けた1問ずつを保存します。上下の余白に加えて**左右の余白も落とす**ので、
ページを丸ごと持つより字が大きく残り、しかも1問あたりは小さくなります。

実測（1500×2000 のページを4問に分割、画質＝最小）：

| | 大きさ |
|---|---|
| 1問あたり | **約8KB** |
| 4問の合計 | 約32KB |
| （参考）ページ丸ごと1枚 | 約11KB |

1問ずつ普通に撮ると1枚 約16KB なので、**まとめて登録したほうが軽い**ことになります。

### 印刷（紙に出して解き直す）

一覧タブの **「🖨 選択したものを印刷」** から、**選ぶ → 完了 → 並べ方 → 印刷** の1本道です。
iPad は印刷画面から「PDFで保存」もできます。

**刷るのは問題の写真と通し番号だけ**です。教科・参考書・ページ番号・日付は入れません。
紙の上では番号さえあれば足り、余白は1問でも多く載せるために使います。

| 選べること | 中身 |
|---|---|
| **どれを刷るか** | 一覧で1問ずつ選ぶ（下記） |
| 並べ方 | 1列 ／ 2列 ／ 3列 ／ 4列。**1ページに何問と決め打ちせず、入るだけ詰める** |
| 写真の大きさの上限 | 20〜120mm のスライダー。小さくするほど1枚に入る |
| 白黒のはっきりさ | **くっきり白黒**（既定）／ グレー ／ そのまま |
| 書き込み欄 | 問題の下に罫線（1列のときだけ） |

#### 流れ

1. 一覧タブで **「🖨 選択したものを印刷」** を押す → 選ぶモードに入る（このボタンは隠れる）
2. サムネイルに丸が出るので **タップで入れる／外す**（このあいだ詳細は開かない）
3. **「完了（N問）→ 並べ方へ」** を押すと、並べ方・白黒・大きさの画面に進む
4. 「N問を刷る」で印刷（またはPDF保存）

- 1問も選んでいないあいだ、完了ボタンは押せません
- まとめて操作：**見えているぶん全部** ／ **復習中だけ** ／ **解除**
- **選んだぶんは絞りこみを変えても残ります。** 参考書を切り替えながら選べば、
  「数学から3問・英語から4問」を**1枚にまとめて**刷れます
- 印刷の並びは **参考書 → ページ → 問題番号 → 登録順**（何冊にまたがっても本ごとにまとまる）
- 「やめる」で選ぶモードを抜け、選択も消えます
- 並べ方の画面の **「一覧で選びなおす」** で、選択を保ったまま2に戻れます

#### モノクロで刷る前提の作り

紙を写真に撮ると、影・紙の日焼け・照明のムラがそのまま入ります。
これをコピー機に通すと薄い字が消えたり、全体が灰色に沈んだりします。

**「くっきり白黒」は Sauvola 法**で、画素ごとに「まわりと比べて暗いか」で白黒を決めます。
ページ全体で1つのしきい値を決める方式だと、影のある側が真っ黒につぶれます。
先に積分画像（足し算の表）を作るので、窓を広くとっても速度は変わりません。
まわりに濃淡が無い場所（＝白紙）はしきい値が下がるため、塗りつぶされません。

枠線・罫線は**すべて黒**です。うすいグレーはモノクロ印刷で飛びます。
罫線は**本物の枠線**で引いています（`background` で描くと
ブラウザの「背景を印刷しない」設定で消えてしまうため）。

#### 詰めこみ

`1ページにN問` の決め打ちをやめ、**`break-inside: avoid` で入るだけ流し込む**方式です。
問題の切り抜きは横長で背が低く、N問固定だと下半分が丸ごと余っていました。

並べているのは grid ではなく **inline-block** です。grid はページまたぎの分割が
ブラウザによって崩れますが、inline-block は行送りで確実に改ページされます。

目安表示は実測に合わせてあります（30問・2列・上限35mm → **実際に3ページ／見積りも1枚10問**）。

| 並べ方 | 1枚におよそ |
|---|---|
| 1列・55mm | 3問 |
| 2列・35mm | 10問 |
| 3列・30mm | 21問 |
| 4列・25mm | 32問 |

### 続けた記録

分析タブに**連続日数**と**カレンダー**（直近15週）が出ます。
**1問でも登録するか、復習を1回でも答えれば**「やった日」になります。

- いま連続 / 最長 / 今月の学習日数
- 今日まだ何もしていなくても、**昨日までの連続は生きている**扱い（今日やればのびる）
- 参考書で絞っているときは出しません（習慣の話なので、いつも全体で数えます）

### 写真の容量対策

1問につき最大2枚。ためこむと端末の保存領域を圧迫するので、4段構えで対処しています。

| いつ | しくみ |
|---|---|
| 撮るとき | **画質プリセット**（既定＝最小 35KB／軽量 80KB／標準 200KB／高画質 680KB）で最初から小さく保存 |
| あふれたとき | `QuotaExceededError` を捕まえて**自動で軽くして保存し直す**（1000px→800pxの2段階） |
| あとから | **「写真を軽くする」** で保存ずみの写真をまとめて縮める（実測 **67%減**） |
| ほっといても | **定着ずみの写真を自動お掃除**（30日後 / 90日後）。写真だけ消え、メモ・記録・分析・復習の予定は残る |

そのほか、迷子写真（どのミスからも参照されていない写真）の掃除、
個別の「写真だけ削除して容量をあける」、残り容量が減ったときの通知バナーがあります。

**記録は絶対に消しません。** 消えるのは写真だけで、「いつ間違えた・何回で覚えた」は全部残ります。

再圧縮は、すでに十分小さい写真には手を出しません（JPEG は再圧縮のたびに画質が落ちるため）。
何度ボタンを押しても無駄に劣化しないようにしてあります。

設定（⚙）→「保存領域」で、**あと何問ぶん入るか**を数字で確認できます。

### データの置き場所
写真もふくめてすべて **端末内の IndexedDB** に保存されます。サーバーには一切送信しません。
GitHub Pages などで公開しても、アップされるのはこの65KBのファイル一式だけで、
写真もノートも1件たりとも外には出ません（＝端末をまたいだ自動同期はありません）。

写真は切り抜き後に、設定の**画質プリセット**（既定＝最小：長辺700px / JPEG 0.58）へ圧縮してから保存します。
元の写真が何MBあっても保存量は変わりません。

実測（3024×2268 の元画像を同じ処理でエンコードした値）：

| 撮り方 | 最小 | 軽量 | 標準 | 高画質 |
|---|---|---|---|---|
| ページ全体（文字びっしり） | 47KB | 110KB | 235KB | 786KB |
| 問題1問だけ切り抜き | 16KB | 37KB | 105KB | 525KB |
| 数式2〜3行の切り抜き | 10KB | 23KB | 77KB | 465KB |
| 暗い部屋・ノイズ多め | 7KB | 18KB | 79KB | 511KB |
| **平均** | **約20KB** | **約47KB** | **約124KB** | **約572KB** |

写真の中身しだいで倍近くぶれるので、アプリ内の見積もりは
これより大きめ（最小35KB／軽量80KB／標準200KB／高画質680KB）で計算しています。
「あと何問ぶん」が実際より少なめに出るぶんには困らないためです。

**問題＋解答の2枚で1問**として、1GB あたりに入る量：

| 画質 | 1問あたり | 1GB で | 毎日3問なら |
|---|---|---|---|
| **最小（既定）** | 約70KB | **約15,000問** | 約13年 |
| 軽量 | 約160KB | **約6,500問** | 約6年 |
| 標準 | 約400KB | **約2,600問** | 約2年4か月 |
| 高画質 | 約1.4MB | **約770問** | 約8か月 |

既定を最小にしているのは、**問題を1問だけ切り抜いて撮る**という使い方なら
長辺700pxでも文字がはっきり読めるからです（等倍で目視確認ずみ。
教科書のページ全体でも本文まで読めましたが、字はかなり小さくなります）。
ページを丸ごと撮ることが多いなら「軽量」か「標準」にしてください。

⚙設定 →「写真の画質」に、**いま持っている写真が画質ごとに何MBになるか**が
棒グラフで並びます。切り替える前に、どれだけ減るか見てから決められます。

実際に使える容量と**あと何問ぶん入るか**は ⚙設定 →「保存領域」に出ます。
画質を変えても、すでに撮ったぶんは「写真を軽くする」を押せばまとめて縮められます。

### データが消える条件と対策
| 条件 | 対策 |
|---|---|
| ブラウザの「閲覧データを削除」 | **防げない。** 定期的な書き出しが唯一の対策 |
| 端末の空き容量が尽きたときの自動削除 | 起動時に `navigator.storage.persist()` を要求して対象外にしている |
| iPhone の Safari / Chrome で7日間開かなかった | Safari から「ホーム画面に追加」すると対象外になる |

20問以上ためていて30日以上バックアップしていないと、復習を終えた画面で書き出しをうながします。
設定（⚙）→「保存領域」で、写真の枚数・使用量・残り容量・自動削除の保護状態を確認できます。

## 検証ずみの動作

Playwright（Chrome, 414×900）で以下を実機相当で確認済み。

- 写真の選択 → ドラッグで範囲選択 → 切り抜き → サムネイル反映
- 登録 → IndexedDB 保存 → リロード後も復元
- 「できた」で step +1・次回16日後 ／ 「またミス」で step 据え置き・翌日＋当日再出題
- セッション完走 → 完了画面
- 書き出し → 全消し → 読み込みで写真ごと復元（Blob として復元されることを確認）
- 1日の上限（3問に設定 → 5問中3問だけ出題）
- バックアップ催促の出し／引っこめ（20問未満は出ない・「あとで」で7日消える・書き出し後は消える・31日後に再出現）
- 設定の保存領域カード（使用量・残り容量・自動削除の保護状態を表示、Chrome では自動でON）
- 参考書の登録・改名（登録ずみのミスの表示も追従）・削除（ミスは残る）
- ショートカット → その場で写真選択が開く → 参考書と教科が入った状態で登録
- 登録後も追加画面に留まり、参考書は選ばれたまま・ページ番号だけリセット
- 一覧の参考書フィルタ、分析の「参考書ごとのミス」、詳細の参考書・ページ表示
- 続けた記録（7日連続・穴あき・40日前の復習のみの日 を仕込んで、連続7／最長7／全15日を確認）
- ページから複数問（1500×2000 の4問ページ → 自動で5分割＝見出し＋4問、OCRで番号 1,2,3,4 を読み取り、
  見出しを自動で「とばす」、参考書・ページを引き継いで4問を一括登録）
- 音の宣言（偽の Audio Session API を差しこんで、start で `auto → ambient`、
  stop で `ambient → auto` に戻ることを確認。ambient のときだけ失敗するカメラを作って、
  宣言を取り下げて起動し直す保険が働くことも確認。API が無い環境では何も起きない）
- 印刷の流れ（「選択したものを印刷」→ 選ぶモード（印刷ボタンは隠れる・完了は押せない）→
  3問選ぶと「完了（3問）→ 並べ方へ」→ 押すと並べ方の画面が開く →
  「一覧で選びなおす」で選択を保ったまま戻る →「やめる」で解除）
- 印刷の選択（青チャートで2問 → 参考書を英語に切り替えても選択が残る →
  さらに1問足して3問 → 印刷対象が参考書ごとにまとまって並ぶ）
- 印刷（30問から2問を外して28問、「見えているぶん全部／復習中だけ／解除」、1〜4列、
  くっきり白黒で紙の色と影が消えること、教科・参考書が刷られないこと。
  `emulateMedia('print')` と `page.pdf()` で 30問・2列35mm → 3ページを確認）
- 参考書を選ばない登録は今までどおり復習画面に戻る
- 書き出し → 全消し → 読み込みで、参考書一覧とページ番号ごと復元

iPad（820×1180 / 1180×820）でも通しで確認済み。

- 参考書が教科ごとにまとまって並ぶ（ショートカット・追加のチップ・設定・一覧の絞り込み）
- ページ／問題番号の数字2欄・「前回のつづき」候補（`p.132 問6` / `p.132` / `p.133`）のワンタップ入力

- 「この本を通して復習する」でその本だけをページ順に出題
- 設定・分析からノートを開ける
- iPad 縦横・iPhone 幅すべてで横スクロールなし、下タブは下に固定のまま
- アプリ内キーパッド（タップで開く／数字と⌫／「次へ」で問題番号へ／「完了」と外タップで閉じる／閉じても値は残る）
